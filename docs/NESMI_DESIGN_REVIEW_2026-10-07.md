# Nesmi 设计评估与竞品分析 — 2026-10-07

## 目标与证据边界

目标用户是共同管理家务的家庭、伴侣与室友。本版围绕三个问题展开：今天需要做什么、谁负责、已经完成多少。竞品分析用于确定产品与交互取舍，不用于声称增长、留存或健康效果。

本评估依据当前仓库的 `App.tsx`、`ListView.tsx`、`ChoreModal.tsx`、`CompletionDialog.tsx`、`types/index.ts`、`recurrence.ts`，以及下列竞品官方页面。改版范围与验收标准是交付要求；具体开发、测试和发布状态以实际提交及验证记录为准。

品牌依据：最新提交 `168c05a` 为 “Rebrand Nesmi web and native display names, preserving app identity”。因此保留 **Nesmi** 名称；`/chorely/` 是现有访问路径，原有应用身份不因本次设计改版更改。

## 当前体验观察

| 可观察事实 | 对体验的影响与判断 |
| --- | --- |
| 原代码桌面默认 Calendar，手机默认 Today。 | 推论：用户的第一步随设备改变，桌面使用者需要先理解日历才看到今天的行动清单。 |
| Today 已有日期选择、负责人筛选、逾期/今日/已完成分组和任务完成入口。 | 这些能力足以支撑本版核心，不需要先扩展新的任务系统。 |
| 原清单只显示任务总数，没有明确的当日完成比例。 | 推论：用户难以快速判断今天还剩多少工作。 |
| 创建表单已有负责人、日期、重复、分类和可选估算时长。 | 可呈现真实负责人、分类和时长；不能根据任务名称擅自猜测耗时。 |
| 原空状态从手动创建开始，未提供常用家务草稿。 | 推论：第一次使用时需要自己想出并输入任务，增加启动负担。 |
| 完成记录保存对应任务、发生日期和完成者；未分配任务需要明确选择完成者。 | 保留明确记账语义，不能默认把功劳给家庭列表中的第一个人。 |
| 当前重复任务实例生成器继续使用任务原负责人。 | 类型或辅助函数中存在自动分配字段，不足以证明自动轮值已经贯通实际重复任务流程。 |

## 官方竞品分析

以下是官方声明的产品能力，并非本团队独立验证的用户效果。页面核查日期：2026-10-07。

| 产品与来源 | 官方页面说明的能力 | 对本版的具体启发 |
| --- | --- | --- |
| [Tody](https://todyapp.com/)；[官方 FAQ](https://todyapp.com/faq) | 根据各项家务频率和上次完成时间呈现到期程度；按房间拆成小任务；生成今日短清单；支持责任分配、轮值及贡献可见性。 | Today 成为统一默认入口；保留到期日期与负责人；让逾期工作可见，但不淹没今日进度。 |
| [Sweepy](https://sweepy.com/) | 提供常用家务建议和自定义任务；可按难度与脏污程度筛选；智能日程依据用户每日可投入精力生成清单。 | 提供可编辑的常用家务草稿；显示用户实际填写的估算时长，支持更有把握地选择下一项工作。 |
| [Nipto](https://nipto.app/) | 重复计划、任务轮值、今日任务快速完成、家庭贡献记录；个人目标与奖励可配置；儿童可作为受管理成员使用。 | 优先让今日行动、责任归属和真实完成结果容易看见；现有积分不应占据核心任务流程；新的轮值、奖励或儿童审批系统另设范围。 |

产品推论：这些产品的共同基础是把记忆与协调工作转化为可见的任务、责任和完成反馈。Nesmi 本版采用这一基础，并结合 Empathie 简洁、克制的视觉风格。竞品提供某项能力并不意味着 Nesmi 本版需要复制全部能力。

## 本版范围与优先级

1. **统一行动入口。** 桌面与手机默认 Today；日期、任务、负责人和完成操作有清楚的信息层级。Calendar、All chores、Insights 和 Account 保留为可访问目的地。
2. **显示真实进度。** 当前日期的已完成/总任务采用同一成员范围计算。搜索词和完成状态筛选不改变这个进度分母；逾期任务单独列出。
3. **缩短首次创建。** 提供常用家务建议，选择后进入可编辑表单；用户确认保存之前不写入任务。保留自定义创建。
4. **提升任务可判断性。** 任务行显示真实负责人、日期及可用的估算时长或分类；创建表单保留可选时长/分类以及其他高级设置。
5. **恢复清楚可用的界面。** 更新登录页、主题视觉、Header、导航和相关样式；筛选无结果时提供清除筛选入口；维持清楚的保存中、错误与重试状态。

排序依据是进入任务的速度、责任清晰度、现有数据与逻辑的可复用程度，以及对现有账号与任务数据的风险。

本版不增加新的自动轮值、智能调度、奖励经济、家长审批、多人账号邀请或同步后端。原生 iOS/Android、Chrome 扩展及商店版本不会因本次 Web 改版自动完成重建或提交。

## 用户故事与验收标准

| 场景 | 可观察的验收标准 |
| --- | --- |
| 我打开应用，想知道今天做什么。 | 桌面与手机均默认 Today；主要任务行无需打开详情即可看到名称、负责人、日期和完成入口。 |
| 我切换日期，想知道当天的进度。 | 进度为该日期、当前成员范围内的已完成实例数/全部实例数。零任务时不显示无意义百分比。 |
| 我搜索或只看未完成任务。 | 搜索/状态筛选改变显示的结果，但不改变该日期进度分母；进度文案清楚表明日期及成员范围。 |
| 我有逾期任务。 | 逾期任务独立分组，不计入所选日期的完成比例。不会把未来任务显示为逾期。 |
| 我第一次创建任务。 | 常用建议填入可编辑草稿；标题、日期和负责人可修改；没有确认保存时不创建记录；自定义任务仍可创建。 |
| 我想选择适合当前精力的工作。 | 只显示真实保存的估算分钟或分类；缺少时长时不编造数值，也不伪装成智能估算。 |
| 我筛选后没有结果。 | 空状态区分没有任务与没有匹配结果；有筛选时提供 Clear filters，并恢复可见任务。 |
| 我完成一项重复任务。 | 只记录指定发生日期的完成状态；其他发生日期保持原状态；完成者需明确，未分配任务不默认选择第一个成员。 |
| 我撤销完成或网络失败。 | 撤销仅作用于该条完成记录；提交中防止重复提交；失败给出可理解的错误并允许重试，不丢失表单内容或误报成功。 |
| 我在手机上操作。 | 390px 宽度下无水平溢出；输入字号至少 16px；主要点击区域至少 44px；弹窗、键盘和底部安全区不遮住主要操作；键盘焦点可见。 |
| 我的数据正在加载或加载失败。 | 加载/错误与真正空家庭区分，失败状态提供 Retry；不把读取失败描述为用户没有任务。 |

## 指标与待验证假设

当前没有本次改版的可靠基线。下列指标是待采集的测量定义，不代表已经接入分析系统，也不设未经校准的数值承诺。已有 GTM 文件中的数值应视为产品目标，不能作为实际表现引用。

| 指标 | 事件、分母与窗口 | 验证目的 |
| --- | --- | --- |
| 首个任务创建率 | 经验证的新注册账号中，24 小时内发生首个 `chore_create_succeeded` 的账号数/经验证的新注册账号数；按注册周分组。 | 检验常用任务草稿及登录体验是否帮助用户开始。 |
| 创建成功率 | `chore_create_succeeded` / `chore_create_attempted`；按周汇总，同一次重试用关联标识保留。 | 检验创建流程和保存可靠性。 |
| 完成保存成功率 | `completion_save_succeeded` / `completion_save_attempted`；按周汇总，并记录失败类型。 | 检验完成操作是否可靠，而非仅根据界面动画判断。 |
| 首次创建耗时 | 从首次进入已登录空状态到首个创建成功的时间；报告中位数和 p75，另列未完成用户。 | 检验首次创建的阻力。 |
| 每周到期任务完成率 | 在同一周计划到期的任务实例中完成的实例数/当周计划到期实例数；排除删除项并单独记录改期，统一账号本地日期口径。 | 检验任务是否从计划走向行动，避免只统计创建量。 |
| 使用后反馈 | 小规模试用后的访谈：是否更清楚今天做什么、谁负责，以及是否减少重复提醒；保留原话并注明样本。 | 验证任务清晰度是否改善实际家庭协调。 |

采集建议：客户端记录界面入口与尝试事件，保存成功以实际持久化结果为准；不要记录任务名称、私人备注或其他不必要的家庭信息。首次形成基线后再确定目标和比较窗口。

重要测量限制：当前 `completedBy` 代表登记的家庭成员，可能由同一个登录账号代为填写。因此可以报告“被记账的贡献者”，不能据此宣称存在多个独立登录的活跃成员或跨账号家庭参与。
